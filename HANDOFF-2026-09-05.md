### #336 — embedded summarisation
**Decision: Apple Foundation Models, behind a flag, default off.** Full rationale in
`docs/embedded-summarisation-decision.md`. The short version: llama.cpp's advantage (8B quality,
long context) is *already shipped* via the local-Ollama backend, so embedding it re-implements an
existing feature for a 4.7 GB download and a C++ dependency. Foundation Models instead buys
something new — **zero install** — for about a day's work, and is cheap to withdraw. Private Cloud
Compute was rejected despite its 32k window because it is Apple's cloud and Distavo promises no
cloud path. MLX Swift is the named successor if the long-context route is ever revisited.

Measured on this Mac (macOS 26.6, Xcode 26.6) rather than taken from documentation:
`contextSize` = **4096** (input *and* output), Distavo's existing prompt template alone = **779
tokens**, density 4.10 chars/token. That leaves ~1800–2600 tokens of transcript per pass, about
10–15 minutes of speech; a one-hour meeting is ~7× over budget, hence map-reduce.

Architecture follows the transcriber's split: pure budgeting/chunking in dependency-free
`DistavoCore/EmbeddedSummary.swift`, the engine in `DistavoEmbedded/EmbeddedSummariser.swift`
behind `#if canImport(FoundationModels)` + `@available(macOS 26, *)`. The reduce step reuses
`Prompt.build`, so an on-device note has the same shape as an Ollama one and faces the same
`SummaryValidator`.

The flag is a real kill switch: with `summarise.embedded_enabled` false, `backend == "embedded"`
falls back to Ollama rather than failing, and Settings does not offer the engine.

## 2b. Field test on a real recording (added after the first pass)

Marc supplied a real **97-minute** meeting. Run through the full embedded pipeline and A/B'd
against Ollama on the same transcript. **This is the most important thing in this note.**

**It found a real bug.** The first run failed with `exceededContextWindowSize`. Two defects:
`charsPerToken` was calibrated at 4.0 on the prompt template (prose, 4.10) while real transcripts
measure **3.46** and a bare `SPEAKER_00:` line **2.22** — a 15% under-count (8140 estimated vs
**9403** actual) — and the budget allocated the window to the last token, which the model rejects.
Fixed in `53dad11`. Synthetic transcripts were too tidy to catch it.

Results after the fix (transcription 371 s for 97 min, ~16× realtime, 356 turns, 4 chunks):

| | on-device 3B | Ollama `llama3.1:8b` |
|---|---|---|
| Time | 73 s | 34 s |
| Sections | 16/16 | 16/16 |
| Action rows | **6** | 1 |
| `SummaryValidator` | clean | clean |

**The on-device note held up better than expected and the 8B model worse.** Ollama wrote nicer
prose but **hallucinated** — expanded "EBI" to "Enterprise Business Intelligence" (it is the
European Bioinformatics Institute) and speculated about a speaker's employer, both forbidden by the
prompt — echoed instruction text into the output, and found one action item to the on-device
note's six. Map-reduce did not hollow out the meeting.

One meeting, one sample. But the architecture is sound and the quality is usable, which is what the
flag was gating. Notes are in the session scratchpad (`ebi-run/note-embedded.md`,
`note-ollama.md`) — they contain real meeting content, so move or delete them as you see fit.

Retry / stage-test path (safe: `dry_run` defaults **true**):

```sh
# Dry run first — prints the mutations without performing them.
gh workflow run submit-appstore.yml -f dry_run=true -f until=submit

# The real submission (only after the dry run looks right):
gh workflow run submit-appstore.yml -f dry_run=false -f until=submit

gh run watch "$(gh run list --workflow=submit-appstore.yml --limit 1 --json databaseId -q '.[0].databaseId')"
```

`version` / `build_number` are optional — blank reads them from `apple/project.yml`.

## 5. Traps found along the way (now in `distavo-native-verify`)

- **Per-edition builds must use the real scheme.** The documented loop built `-scheme Distavo` with
  an `-xcconfig` override, which links Sparkle every time because the target is always `Distavo`.
  Use `Distavo-AppStore` / `Distavo-Setapp` with a separate `derivedDataPath` each.
- **Xcode 16+ Debug builds put the code in `Distavo.debug.dylib`.** `strings` on
  `Contents/MacOS/Distavo` (a 40 KB launcher) reports every symbol absent, making a broken gate
  look like a working one.
- **`Links.*URLString` constants are ungated dead data** in every edition — assert on the menu
  label, not the URL. The Lemon Squeezy URL is already in the App-Store-reviewed 1.9.1 binary.
- **Stale `.build` module cache** from the repo's old `/Users/marc/Distavo` path fails every target
  with `missing required module 'SwiftShims'`. `rm -rf apple/*/.build`.
- **`xcodebuild` pollutes `apple/DistavoEmbedded/Package.resolved`** with the app's Sparkle pin and
  downgrades its format. Revert before committing.
